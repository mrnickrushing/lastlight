# Asset coverage audit

What in the world is a reviewed asset and what is still hand-built primitives.
Generated by reading every `part(...)` call and every `assetId` placement in the
world builders, then cross-referencing
[`assets/meshes/manifest.json`](../assets/meshes/manifest.json).

Re-derive it the same way before trusting these numbers again — they are a
snapshot, not a live view.

## Where things stand

| | Count |

410 against 53 is the headline. Most of the world is still primitives. That is
not automatically wrong — terrain, roads, floors, walls, roofs, collision
shells, and invisible anchors are *supposed* to be purpose-built geometry, and
`VISUAL_QUALITY_STANDARD.md` says so. What matters is the inspectable props, and
those are covered unevenly.

## Gap 1 — enemies have no assets at all

`BramblewakeEnemyBuilder.luau` contains **zero** references to `assetId`,
`MeshTemplateLoader`, or `MeshPart`. Every enemy is assembled from primitives:

`BackThorn`, `BarkRamCore`, `BriarLeg`, `BriarbackCore`, `CrowBeak`, `CrowWing`,
`DrowsyTrail`, `FrontShield`, `HollowCrowCore`, `JawThorn`, `MossBack`,
`MossCrown`, `PollenHeart`, `PollenPetal`, `RamBrow`, `RamHorn`, `RamLeg`,
`ReadableEye`, `RootArm`, `RootCore`, `ShieldTusk`, `SnapJaw`, `SnapvineRoot`,
`StolenSpark`, `VineStem`

This is the single largest coverage gap, and enemies are inspected at close
range in combat. Note the constraint before replacing them: the standard
requires cosmetic geometry never to alter authoritative combat bounds, so an
enemy asset has to sit over the existing hitbox rather than become it — the same
replace-only-the-visible-shell contract the landmarks already use.

## Reading the placement code correctly

Two traps, both of which produced a wrong answer on the first pass of this
audit:

1. **`assetId` is not always a string literal.** The conifers are assigned
   through a conditional:

   ```lua
   assetId = if treeSeed % 2 == 0
       then "mesh_conifer_hero_a"
       else "mesh_conifer_hero_b",
   ```

   A `grep` for `assetId = "` misses both and reports the hero trees as unused.
   They are placed — on roughly a third of band-1 trees, by design, to stay
   inside the mesh budget.

2. **A mention is not a placement.** `mesh_lantern_post_a` appears in
   `WorldService.luau` only inside `placement.assetId == "mesh_lantern_post_a"`,
   a comparison that tunes jitter. Counting mentions makes it look placed.

## What "no blocky placeholders" actually requires

The visual standard already draws the line: structural shells, collision,
terrain, and roads may stay purpose-built; inspectable props and practical-light
vessels must use reviewed art. Against that line the open work is:

- enemies (Gap 1) — nothing sourced at all;
- cabin interior smalls — shelf supplies and bedrolls are still plain boxes;
- whatever a Studio pass turns up that this static read cannot see.

A static audit cannot tell you whether a placed asset *looks* right, only
whether one is placed. Scale, orientation, and clipping need Studio.

## Rotated cylinders

A Roblox `Cylinder` extends along its **local X axis**, so its size reads
`(height, diameter, diameter)`, and `diameter != diameter` gives an ellipse.
Authoring one the intuitive way — `(diameter, height, diameter)` with no
rotation — lays it on its side. Five props shipped that way and have been fixed;
`HeartwoodStump` additionally came out oval and a stud too tall.

Auditing for this by script is unreliable in both directions: a rotation
belonging to a neighbouring part reads as a false negative, and a rotation
applied on the line *after* the `Shape` assignment reads as a false positive.
Every candidate needs reading in context.
